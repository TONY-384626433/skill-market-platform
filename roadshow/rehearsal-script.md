### 【PPT 2: 痛点引入 —— "九江银行的 AI 之痛"】1 分 30 秒

```
⏱ 剩 13:00

"在座各位可能好奇 —— 银行为什么需要一个 AI 技能市场?

我们先看一组数据 ——

九江银行信息科技部在 Dify 平台上已经创建了 80+ 个 AI 工作流,
但其中有 35% 功能高度重复。为什么?

因为 A 团队做的东西, B 团队不知道。C 团队又从头开始造轮子。

我给大家讲三个真实的场景:

场景一: 运维一部花 3 周做了一套数据库巡检工具。
运维二部不知道, 又花 2 周做了一套几乎一样的东西。
DBA 团队更不知道, 也用 Python 写了一套。

三个团队, 7 个人周, 做着同一件事。

场景二: 安全团队发现, 全行 AI 工具的 API Key 散落在
配置文件、环境变量、甚至代码硬编码里。
谁、什么时候、用什么权限、访问了什么数据? —— 查不到。

场景三: 新员工入职, 不知道行里有哪些 AI 武器可用。
老员工离职, 积累了半年的 Prompt 模板和 Agent 配置
也跟着走了。

这三个场景背后, 是同一个根问题: AI 能力碎片化, 缺乏统一治理。

这就是我们要解决的问题。"
```

### 【PPT 3: 解决方案 —— 一句话】1 分钟

```
⏱ 剩 12:00

"我们的方案很简单 ——

建一个九江银行自己的 'AI 应用商店'。

对标的是腾讯内部的 SkillHub, 
但我们不是照搬, 而是针对银行场景做了深度适配。

核心就 8 个字: 建得起、找得到、用得安、管得住。

- 建得起: 开发者通过标准化模板, 分钟级创建技能
- 找得到: AI 语义搜索, 输入'我想做数据库巡检'就能找到对应技能
- 用得安: 七层安全防护, 每一次调用可审计可追溯
- 管得住: 全生命周期管理, 从审核到退役

我们本质上是一个 AI 基础设施项目 ——
不是做一个具体的 AI 应用, 而是做一个让所有 AI 应用
能够被管理、被复用、被治理的平台。"
```

### 【PPT 4: 系统架构】2 分钟

```
⏱ 剩 10:00

"来看架构。我们采用四层设计:

最上层是展示层 —— Web Portal。
技能市场的首页、智能搜索、一键安装、开发者工作台。
连接了超过 150 个内部用户。

第二层是 API 网关层。
所有的技能调用都要经过这个统一网关,
实现鉴权、限流、协议转换。

第三层是核心服务层。
左边是市场运营服务 —— 技能目录、智能搜索、评价体系。
中间是技能生命周期服务 —— 注册、审核、版本管理、一键部署。
右边是安全管控服务 —— 身份认证、权限鉴权、全链路审计。

最下面是技能运行底座。
这就是我们跟其他平台最大的不同 —— 
我们不是再造一套 AI 引擎, 而是对接九江银行已有的基础设施:
Dify 工作流引擎、自研 Agent 调度框架、MCP 协议网关,
以及下面的 PostgreSQL、Redis、ELK、Zabbix、CMDB。

重点看中间的技能定义模型 ——
每一个技能用标准化的 YAML 描述文件注册。
包含: 基本信息、接入协议、依赖声明、权限要求、
接口定义、质量指标、使用示例。

这不是拍脑袋定的 —— 我们是深度调研了 MCP 协议规范、
Dify 工具市场、以及腾讯 SkillHub 的实践之后,
结合银行金融场景的特殊要求, 定义的企业级技能描述规范。"
```

### 【PPT 5: 核心功能 —— 技能发现】1 分 30 秒

```
⏱ 剩 8:30

"接下来展示几个核心功能。

首先是技能发现。这个页面上 ——

左侧是分类浏览: 智能运维、研发效能、安全合规、数据治理。
每个分类下有技能数量和热度。

中间是 AI 驱动的智能搜索。
关键区别在于 —— 这不是关键字匹配, 而是语义理解。

你输入'我想做数据库慢查询分析',
系统会 Embedding 理解你的意图,
从技能描述、标签、使用场景中匹配最相关的技能。

右侧是个性化推荐。
不同角色看到的推荐不一样:
DBA 看到的是数据库巡检、慢查询分析;
开发看到的是代码评审、部署助手;
安全看到的是日志脱敏、漏洞扫描。

这就是 '找得到'。"
```

### 【PPT 6: 核心功能 —— 技能发布与审核】1 分 30 秒

```
⏱ 剩 7:00

"再看开发者侧 —— 如何把技能发布到市场。

我们支持 6 种技能形态:
MCP Server、Dify 工作流、Agent 模板、API 封装、
Prompt 模板、知识库。

开发者只需要选择形态、填写信息、配置接口, 三步完成提交。

提交后进入自动化审核流水线:

第一关: 格式校验 —— 检查 YAML 结构完整性
第二关: 安全扫描 —— SQL 注入、XSS、敏感信息泄露
第三关: 功能验证 —— 自动调用接口, 检查可用性

三关全过, 自动上架。有失败, 即时反馈修改。

整个过程全自动化, 不需要人工排队审核。
这也是银行里少有的'低摩擦'流程。"
```

### 【PPT 7: 核心功能 —— 安全管控】1 分 30 秒

```
⏱ 剩 5:30

"银行场景下, 安全永远是第一位。

我们实现了七层安全防护:

第一层: 身份认证 —— 对接 LDAP, 你知道是谁在操作
第二层: 权限校验 —— RBAC, 用户权限和技能权限取交集
第三层: 限流控制 —— 基于 Token 的 QPS 管控
第四层: 敏感信息检测 —— 输入参数实时检测, 发现身份证号等立即阻断
第五层: 协议适配 —— 安全转发到技能后端
第六层: 输出脱敏 —— 返回结果再次检测和脱敏
第七层: 全链路审计 —— 每一次调用的完整审计轨迹

每一层都对应一条审计日志,
可以回答: 谁、在什么时间、用什么技能、访问了什么数据、
用了多少 Token、结果是什么。

这个审计能力——如果现在银行没有 AI 技能市场,
是不可能实现的。"
```

## 四、第 1 遍排练自检清单

- [ ] 计时: 总时长是否在 15 分钟 ± 30 秒?
- [ ] 语速: 是否过快 (>180 字/分钟) ?
- [ ] 眼神: 是否大部分时间在看评委而非屏幕?
- [ ] 停顿: 关键数字/结论是否有 1-2 秒停顿?
- [ ] 衔接: PPT 切页是否自然? 演示切换是否卡顿?
- [ ] 术语: 是否对非技术评委解释了专业术语?
