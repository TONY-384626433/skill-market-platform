# SkillHub 15 分钟路演排练稿

原则：只陈述当前系统可验证的能力。规划项必须明确称为“下一阶段”，不把目标数据说成现状。

## 1. 项目定位（1 分钟）

SkillHub 是九江银行内部 AI 能力目录与治理平台。它解决的不是单个 AI 应用问题，而是内部能力分散、重复建设、接入凭据失管和调用无法追溯的问题。

核心价值可以概括为四点：能力找得到、接入可撤销、发布要审核、调用可追溯。

## 2. 用户与流程（2 分钟）

平台有三类角色：

- 普通用户浏览、安装、试玩、评价和卸载技能。
- 开发者提交技能 Manifest、依赖、权限和接口定义，并跟踪审核反馈。
- 管理员复核提交、通过或驳回，并查看全量调用审计。

服务端通过 JWT 和角色中间件校验权限。菜单隐藏只是体验优化，不是安全边界。

## 3. 技能市场（2 分钟）

当前市场内置 4 个真实 MCP 技能：数据库巡检、日志脱敏、告警收敛和需求分析。首页数量、安装量、近 30 日调用、成功率与分类计数都从 PostgreSQL 实时计算。

当前检索支持名称、简介和标签的关键词匹配，以及分类、接入形态和排序筛选。向量语义检索属于下一阶段，不在当前版本中宣称已完成。

## 4. 真实调用与安装（2 分钟）

在线试玩经过 Go 统一网关，通过 JSON-RPC over MCP 转发到 Docker 中的 skill-runner。结果包含耗时和 Trace ID，并写入审计表。

安装时使用加密安全随机源生成独立令牌，数据库只保存 SHA3 哈希和前缀。卸载后令牌立即失效；重新安装会轮换令牌，不会复用旧凭据。

## 5. 发布与审核（2 分钟）

开发者按四步提交：基本信息、接入配置、权限治理、确认提交。提交后状态为待审核，不会直接出现在市场。

管理员在治理工作区核对能力边界、接入地址、权限和责任归属。通过后技能公开发布；驳回必须填写整改原因，开发者可在“我的发布”中看到反馈。

当前实现的是可执行的人工复核闭环。自动安全扫描和自动功能验证是后续可接入的审核阶段，不把它们表述为已上线能力。

## 6. 安全与审计（2 分钟）

当前版本已实现：

- bcrypt 密码哈希和 JWT 身份认证。
- HMAC 签名算法约束和服务端角色权限。
- 安装令牌哈希存储、撤销校验与安全轮换。
- 敏感关键词输入拦截，脱敏技能使用受控白名单。
- 用户、技能、方法、状态、耗时、来源 IP、PII 标记和 Trace ID 审计。

需要如实说明：生产落地还需接入银行 IAM/LDAP、TLS 终止、密钥托管、限流、细粒度数据权限和合规留存策略。

## 7. 技术架构（2 分钟）

- 前端：React 18、Ant Design、Vite，支持桌面和移动端。
- API：Go、Gin、PostgreSQL、JWT。
- 技能运行：Python 容器、MCP JSON-RPC、统一 HTTP 转发。
- 基础服务：PostgreSQL、Redis、MinIO、Docker Compose。

Redis 和 MinIO 已纳入运行底座，但当前核心业务读写以 PostgreSQL 为主。不要声称当前版本已使用 Elasticsearch、RabbitMQ、Vault 或 Kubernetes。

## 8. 验证结果与下一步（2 分钟）

当前版本已完成以下验收：

- 市场、详情、登录、开发者和治理页面在桌面与手机视口无横向溢出。
- 真实技能调用成功；撤销令牌后调用返回 403；重新安装会轮换令牌。
- 普通用户访问开发者和管理员接口返回 403。
- 开发者提交、管理员审核、驳回意见回传形成完整闭环。

下一阶段优先级：接入企业 IAM、增加自动安全扫描、引入向量检索、补充版本回滚与灰度发布、建立生产级可观测性。

## 收尾话术

SkillHub 当前已经不是静态原型，而是一条可以实际运行和验证的内部能力治理闭环。我们不以虚构数量证明价值，而以真实调用、真实权限和真实审核流程证明方案可落地。
