# SkillHub 评审问答手册

回答原则：先说明当前已实现，再说明生产化差距和下一步。不要把路线图说成现状。

## 产品定位

### 1. 这和 Dify 工具市场有什么区别？

Dify 更接近 AI 应用编排与工具使用环境；SkillHub 解决企业内部能力的统一目录、角色权限、发布审核、独立凭据和调用审计。两者可以集成，但当前版本没有宣称已完成 Dify 自动注册。

### 2. 为什么不直接建一个 MCP Registry？

Registry 解决“在哪里找到服务”，但银行内部还需要谁能发布、谁能审核、谁安装过、令牌是否可撤销、敏感输入是否被阻止和调用能否追溯。SkillHub 在目录之上补了治理闭环。

### 3. 当前不是只有 4 个技能吗？

是。4 个技能都能由容器真实执行，用于验证不同类型的企业场景和完整流程。当前重点是证明底座可运行，而不是用硬编码数量营造规模。规模化需要后续接入真实内部能力供给。

### 4. 如何衡量平台价值？

建议关注复用率、重复建设减少量、从发现到可调用的时间、审核周转时间、活跃安装数、调用成功率和安全事件处置时间，而不是只看技能数量。

## 技术实现

### 5. 搜索是语义搜索吗？

当前不是。当前使用 PostgreSQL 对名称、简介和标签做关键词检索，并提供结构化筛选。向量召回、重排和权限感知的语义检索属于下一阶段。

### 6. 在线试玩是真的调用吗？

是。Go 网关将请求转换为 MCP `tools/call`，转发到 `skill-runner:8081`，再返回真实结果、耗时和 Trace ID。Docker 中包含 4 个实际技能服务。

### 7. 为什么后端用 Go，技能用 Python？

Go 适合高并发网关、清晰的权限中间件和稳定部署；Python 适合 AI 工具与数据处理生态。两者通过标准 HTTP 和 MCP JSON-RPC 解耦。

### 8. 网关会不会成为瓶颈？

当前原型是单实例。生产化需要无状态多实例、连接池、限流、熔断、超时、指标与分布式追踪。现有实现已经设置调用超时并记录耗时，但还未完成生产容量设计。

### 9. Redis 和 MinIO 用在哪里？

它们已纳入 Docker 底座，为后续缓存、会话、制品和扫描报告存储准备。当前核心市场、审核和审计数据仍由 PostgreSQL 承担，不能声称二者已承载关键业务。

### 10. 支持哪些技能形态？

发布模型支持 MCP、REST API、Dify 工作流、智能体和提示词类型。当前可真实执行的种子技能全部是 MCP；其他形态仍需要对应适配器才能进入统一调用网关。

## 安全与合规

### 11. 密码和 Token 如何保护？

密码使用 bcrypt 哈希。安装 Token 由 `crypto/rand` 生成，数据库保存 SHA3 哈希和前缀，完整 Token 只在安装成功时返回一次。卸载后令牌立即失效，重新安装会轮换令牌。

### 12. 如何防止越权？

JWT 中包含角色，服务端使用 `RequireRole` 保护开发者和管理员接口。普通用户直接请求这些接口会返回 403。前端菜单隐藏不承担安全职责。

### 13. 敏感信息检测准确率是多少？

当前实现是关键词级输入拦截，尚未做可支撑准确率承诺的评测。生产化需要规则、实体识别、上下文模型、白名单和人工复核组合，并建立标准数据集评估误报与漏报。

### 14. 审计记录包含什么？

包含 Trace ID、用户、技能、方法、状态、耗时、来源 IP、Token 使用量字段、PII 标记和时间。当前演示环境没有配置监管级不可篡改存储和长期留存策略。

### 15. 是否已经符合银行生产合规要求？

不能这样宣称。当前版本验证了身份、角色、凭据、审核和审计机制。生产上线还需要企业 IAM、网络分区、TLS、密钥托管、数据分级、审批制度、日志留存、漏洞扫描和正式安全测评。

## 发布治理

### 16. 技能会自动上架吗？

不会。提交后进入 `pending_approval`，管理员人工通过后才会公开。驳回必须填写原因，开发者能看到整改意见。自动格式校验、安全扫描和功能验证是可扩展审核阶段。

### 17. 如何保证团队责任归属？

技能记录作者和可选维护团队。市场与详情页展示维护方；审核时管理员可核对责任归属。生产化还应对接组织目录并要求至少两名维护者。

### 18. 如何下架有风险的技能？

数据模型已有弃用、归档等状态，但当前 UI 重点实现发布审核。紧急下架、批量令牌吊销、依赖影响分析和版本回滚是上线前必须补齐的管理能力。

## 落地计划

### 19. 下一阶段最优先做什么？

第一优先是接企业 IAM 和细粒度权限；第二是自动安全扫描和功能验证；第三是版本回滚、灰度发布与下架；第四是语义检索和推荐；第五是生产可观测性与容量治理。

### 20. 当前版本最可信的证明是什么？

不是页面截图，而是可重复验收的行为：真实 MCP 调用成功、撤销 Token 后返回 403、重新安装轮换 Token、普通用户越权返回 403、开发者提交和管理员审核完整闭环，以及桌面/手机浏览器无运行错误。
