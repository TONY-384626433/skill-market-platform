# SkillHub 5 分钟演示手册

本手册只演示当前系统已实现并可现场验证的能力，不使用虚构技能数量或模拟调用结果。

## 演示前检查

- 双击 `start-demo.bat`，等待出现本地或公网访问地址。
- 打开市场首页，确认左下角显示“服务运行正常”。
- 使用 `zhangsan / demo` 演示开发者流程。
- 使用 `admin / demo` 演示平台治理流程。
- 提前确认 Docker 中 `skillhub-runner` 状态为 healthy。

## 0:00 - 0:45 市场与治理指标

1. 打开技能市场。
2. 展示搜索、实时分类和 4 个真实技能。
3. 指出已上架、累计安装、近 30 日调用和成功率均来自数据库。

解说重点：SkillHub 的第一屏就是工作目录，不是宣传页。使用方可以快速判断技能用途、维护团队、稳定性、版本和采用情况。

## 0:45 - 1:30 详情与在线试玩

1. 打开“数据库智能巡检助手”。
2. 展示接口定义和权限声明。
3. 切换到“在线试玩”。
4. 登录 `zhangsan / demo`，使用默认参数执行。
5. 展示真实 MCP 返回、耗时和 Trace ID。

解说重点：请求通过统一网关转发到 Docker 中的 skill-runner，调用结果不是页面写死；每次调用都会形成审计记录。

## 1:30 - 2:15 安装与令牌

1. 点击“安装此技能”。
2. 展示仅出现一次的完整访问令牌并复制。
3. 打开“我的技能”，展示版本、令牌前缀和状态。
4. 说明卸载后旧令牌立即失效，重新安装会轮换新令牌。

解说重点：每个用户和技能使用独立令牌，令牌由加密安全随机源生成，数据库只保存哈希与可识别前缀。

## 2:15 - 3:20 开发者发布

1. 使用 `zhangsan / demo` 登录。
2. 打开“开发者工作台”并点击“发布新技能”。
3. 依次填写基本信息、接入配置、权限与接口定义。
4. 在确认页核对内容并提交。
5. 返回“我的发布”查看“待审核”状态。

解说重点：提交对象包含 Manifest、依赖、权限和接口定义。没有团队绑定的开发者也可提交，审核意见会回传到发布记录。

## 3:20 - 4:20 平台审核

1. 使用 `admin / demo` 登录。
2. 打开“平台治理”。
3. 展示待审核、成功率、平均响应和敏感信息识别指标。
4. 在审核队列中查看刚提交的技能。
5. 选择通过或驳回；驳回时填写明确整改意见。

解说重点：角色权限由服务端强制执行。普通用户访问开发者或管理员接口会返回 403，不能通过手工输入 URL 绕过。

## 4:20 - 5:00 审计收尾

1. 切换到“调用审计”。
2. 查看用户、技能、方法、结果、耗时、Trace ID 和 PII 状态。
3. 回到市场，说明审核通过后技能才会公开展示。

收尾话术：SkillHub 把内部 AI 能力的发现、接入、发布和治理放进同一条可审计流程，做到能力可复用、权限可撤销、发布可审核、调用可追溯。

## 故障处理

- 页面无数据：检查 `http://localhost:8080/api/health`。
- 在线试玩失败：检查 Docker 中 `skillhub-runner` 和 8081 端口。
- 公网地址失效：重新运行 `start-demo.bat` 获取新隧道地址。
- 现场网络不稳定：使用 `http://localhost:4173` 本地地址演示。
